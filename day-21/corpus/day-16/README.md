# День 16 — MCP-клиент и `tools/list`

Задание дня — установить готовый MCP SDK, подключиться к серверу и показать его
инструменты. Поэтому здесь нет самописного JSON-RPC клиента: это нарушило бы условие
«install an MCP SDK/client». Клиент делает только MCP handshake и `tools/list`; ни один
инструмент не вызывается. В этот день агент не обращается к облачной модели.

## Запуск

```bash
# публичный сервер DeepWiki по умолчанию
go run ./day-16

# другой Streamable HTTP сервер
go run ./day-16 -endpoint http://127.0.0.1:8080/mcp

# локальный stdio MCP-сервер
go run ./day-16 -command "go run github.com/modelcontextprotocol/go-sdk/examples/server/everything"

# общий дедлайн handshake + tools/list
go run ./day-16 -timeout 10s

# сохранить наблюдаемый HTTP JSON-RPC обмен
go run ./day-16 -save /tmp/day16-exchange.json

# отдать детерминированные правила и эталоны для витрины, без сети
go run ./day-16 -dump
```

Флаги: `-endpoint` (пусто), `-command` (пусто), `-timeout` (`30s`), `-save`
(пусто) и `-dump` (`false`). Если заданы и `-endpoint`, и `-command`, программа
печатает `укажи либо -endpoint, либо -command` и завершает работу с кодом 2. Неверный
`-timeout` тоже даёт код 2; ошибка подключения, subprocess, протокола или критерия —
код 1; успешный вызов — код 0.

| `-endpoint` | `-command` | транспорт |
|---|---|---|
| пусто | пусто | Streamable HTTP к `https://mcp.deepwiki.com/mcp` |
| задан | пусто | Streamable HTTP к указанному адресу |
| пусто | задан | stdio, дочерний процесс из команды |
| задан | задан | ошибка использования, сеть не вызывается |

`-save` записывает HTTP-запросы и ответы вместе с телами JSON-RPC. Для `stdio` у
транспорта нет HTTP-обмена и SDK v1.8.0 не даёт отдельного wire-hook, поэтому файл
содержит явную JSON-заметку об этом ограничении, а не пустой или выдуманный обмен.

Если файл записать не удалось, программа всё равно печатает полученный список и лишь
затем отдельной строкой сообщает о неудаче сохранения: запрошенный артефакт не создан,
поэтому код возврата 1, но успешный ответ сервера не выбрасывается и не выдаётся за
провал соединения.

## Чего клиент НЕ утверждает

`R1` и `R2` живут в конверте JSON-RPC, который SDK разбирает и забирает себе. На
HTTP-транспорте клиент видит настоящий конверт (он же попадает в `-save`) и проверяет
оба правила. На stdio сырого конверта нет, поэтому `R1` и `R2` помечаются как **не
измеренные**, а не как пройденные, и вывод говорит об этом прямо:
`Критерий: выполнены R3, R4, R5; R1, R2 не измерены`. Завернуть разобранный ответ
обратно в самодельный конверт было бы проверкой собственных лесов, а не сервера.

## Чужой текст и чужой объём

Имена и описания инструментов приходят с сервера, который мы не контролируем, и
печатаются в терминал. Управляющие символы (включая ESC-последовательности, способные
переписать заголовок окна или стереть предыдущие строки) заменяются на `U+FFFD` до
вывода. Тело ответа ограничено `MaxResponseBytes` = 8 МиБ — на четыре порядка больше,
чем реальные ответы (DeepWiki ≈ 1,6 КБ, пример SDK ≈ 8,7 КБ), но не «сколько пришлют».

## Критерий

Успешный `tools/list` обязан пройти все пять правил: `R1` — `jsonrpc` равен `"2.0"`;
`R2` — response `id` совпадает с request `id`; `R3` — есть непустой `result.tools`;
`R4` — у каждого инструмента непустое строковое `name`; `R5` — каждый `inputSchema`
является JSON-объектом. `-dump` печатает эти правила и шесть фиксированных пар
request/response: один положительный пример и по одному отрицательному контролю на
каждое правило. Вердикты в выгрузке вычисляет тот же Go-код, а не записанные вручную
ожидания.

## Зависимости

После `go mod tidy` прямой SDK — `github.com/modelcontextprotocol/go-sdk`. Его граф
требует следующие непрямые модули: `github.com/google/jsonschema-go`,
`github.com/segmentio/asm`, `github.com/segmentio/encoding`,
`github.com/yosida95/uritemplate/v3`, `golang.org/x/oauth2`, `golang.org/x/sync`,
`golang.org/x/sys`, `golang.org/x/time`.

В `go.sum` и выводе `go list -m all` записей больше, чем в `require`: там есть
дополнительные зависимости графа, которые не обязательно линкуются в этот клиент.

## Проверка

```bash
go test ./internal/mcpclient -count=1
go test ./day-16 -count=1
go build ./...
go vet ./...
```

Интеграционные тесты используют in-memory и `httptest` MCP-серверы. Единственное
исключение — тест stdio запускает закреплённый пример SDK `everything`; его следует
запускать с `-count=1`, чтобы кэш Go не выдал старый результат subprocess-пути.
