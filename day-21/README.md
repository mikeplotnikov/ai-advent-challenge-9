# День 21 — индексация документов

День строит два локальных JSON-индекса по замороженному снимку Markdown этого репозитория.
Стратегия `fixed` режет каждый файл окнами по 1 800 рун с перекрытием 180, а `structure`
сохраняет границы и иерархию Markdown-заголовков. Каждый чанк содержит исходный путь, заголовок,
раздел, смещения в файле, число токенов и эмбеддинг.

## Запуск

Нужны локальная Ollama и модель `bge-m3`; облачный ключ не используется.

```bash
ollama serve
ollama pull bge-m3

# построить day-21/index/fixed.json и structure.json
go run ./day-21 -index

# сравнить стратегии на замороженных вопросах и создать RESULTS.md + compare.json
go run ./day-21 -compare

# показать по три результата каждой стратегии
go run ./day-21 -search "как считается цена вызова DeepSeek" -k 3

# выбрать только один индекс или другой адрес Ollama
go run ./day-21 -search "вопрос" -strategy structure -ollama http://127.0.0.1:11434
```

`-index`, `-compare` и `-search` взаимоисключающие. Общий таймаут задаётся флагом `-timeout`
(по умолчанию 10 минут). Каталог `day-21/index/` генерируется локально и не коммитится.

## Почему `bge-m3`

В пробе 28.09 на восьми русскоязычных вопросах `bge-m3` поставила правильный фрагмент на первое
место в 7 случаях из 8, а `nomic-embed-text` из урока — в 2 из 8. На тексте длиной 1 500 знаков
получилось 409 против 1 198 токенов. Это небольшой smoke-тест (`n = 8`), а не общий рейтинг
моделей, но для русского корпуса этого дня он дал практическое основание выбрать `bge-m3`.

Векторы проверяются по L2-норме. Если отклонение от единицы больше `1e-3`, код нормализует вектор
и учитывает это в шапке индекса. Это проверка фактического ответа Ollama, а не утверждение, что
компоненты вектора лежат в диапазоне `[0, 1]`.

## Почему здесь нет облачной LLM

Задание заканчивается на chunking, эмбеддингах, индексе и поиске: генерации ответа в нём нет.
DeepSeek не предоставляет embeddings API, поэтому фиктивный облачный вызов ничего не добавил бы
к пайплайну. Все вызовы этого дня идут в локальную Ollama.
