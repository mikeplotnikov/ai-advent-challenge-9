# День 25 — мини-чат с RAG и памятью задачи

CLI хранит все успешные обмены в JSON и продолжает разговор после перезапуска.
На каждом вопросе DeepSeek извлекает цель, ограничения, термины и уточнения, раскрывает
местоимения для поиска. bge-m3 через локальный Ollama ищет в structure-индексе дня 21;
порог косинуса 0,45, реранкер ≥2, до трёх чанков. Ответ содержит источники и дословные
цитаты из текущего контекста. Если сведений недостаточно, показаны отказ и «Источников нет».
История и память определяют намерение пользователя, но не заменяют источник фактов.

Из корня репозитория, после штатной настройки приложения и индекса дня 21:

```bash
brew services start ollama
go run ./day-25 -chat -session /tmp/day25-demo.json
```

Пиши запросы по одному, `/exit` завершает разговор. Повтори команду для продолжения.
Один запрос без интерактивного ввода:

```bash
go run ./day-25 -ask 'Какие инварианты защищали?' -session /tmp/day25-demo.json
```

Ключ приложение берёт из `DEEPSEEK_API_KEY_DAY25`, затем общего штатного ключа.
Ключи не выводятся и не публикуются. Пользователь самостоятельно настраивает приложение.
Для примеров здесь используются отдельные сессии; не сохраняй личные сведения в публичном репозитории.

Два сценария зафиксированы в `scenarios.json`: по 12 запросов и 12 ответов каждый.
`go run ./day-25 -eval` выполняет живой замер; существующий `run.json` не перезаписывает.
`go run ./day-25 -report` без сети воспроизводит `RESULTS.md` и `showcase.json`.
Полный захват — `run.json`, промежуточные сессии — `eval-sessions/`.
Неудачная первая попытка извлечения памяти сохранена в `experiments/memory-literal-v1/`:
модель перефразировала термин, код отклонил его; до итогового прогона инструкция уточнена.
Архив `citation-retry-v1/` сохраняет частичный прогон и ошибку копирования цитаты;
`goal-alignment-v1/` — полный предыдущий прогон и независимую оценку перед уточнением
инструкции сравнения и подписи табличных чисел. Ни один прежний ответ не удалён.
Промпт уточнялся на тех же сценариях — итоговый замер не является независимым тестовым набором.
`prompts_sha256` покрывает три system-промпта (memory, answer, rerank), а не все шаблоны
и инструкции повтора. Полные отправленные сообщения сохранены в attempts.
В JSON остались пустые поля rewrite от формата дня24: в чате query формируется вместе
с памятью, отдельного вызова rewrite нет; в цену пустое поле не включается.

Витрина: https://challeng.mikeproject.dev/day-25/?record.
Она показывает сохранённые живые ответы; произвольный вопрос задаётся в CLI.

Пределы: один процесс на файл сессии; последние шесть обменов передаются модели,
ранняя цель и ограничения сохраняются отдельной памятью. Память проверяется на дословное
происхождение, но модель может неверно выбрать действующую цель или пропустить ограничение.
Проверка цитат доказывает их происхождение, а не истинность всех утверждений ответа.
Это учебный прототип без авторизации, многопользовательской работы и SLA.

Проверки:

```bash
go vet ./...
go test ./... -count=1
```

Результаты живого прогона — [RESULTS.md](RESULTS.md). Смысловая проверка —
`semantic-review.json`, если присутствует; её выводы являются независимой оценкой,
а не гарантией для новых диалогов.

Независимая Sonnet-оценка: supported 12, unsupported 3, unknown 9. Это экспертное суждение по цитатам, не гарантия.

- state: память retained; итоговая цель addressed. Цель корректно заменена в ходе 6 на «Сравнить объём входа и стоимость state-блока». Ограничения «Только измеренные результаты» и «Без внешних знаний» сохранялись до хода 12, уточнения накапливались. Ход 8 показывает разрыв между хранением и полезным ответом: состояние не потеряно, но переписанный запрос подмешал «по сравнению с полной историей» и привёл к отказу, хотя ответ (1.3) был в корпусе. Устаревшие термины и уточнения (про summary и диск) остались в состоянии после смены цели. В ходе 3 ответ нарушил ограничение «только измеренные», опираясь на описание устройства. Финал (ходы 11–12) отвечает на новую цель: 237 токенов, вход ×2.8, цена ×1.3, числа таблицы и руки сравнения. В ходе 11 база сравнения не названа.

- fsm: память retained; итоговая цель addressed. Цель «Понять защиту переходов FSM» и ограничение «Не менять правила переходов» сохранялись во всех 12 ходах, ограничение «Только сведения из базы» добавилось в ходе 3, и потеряно ничего не было. Хранение состояния при этом не равно полезности: 6 из 12 ходов — отказы (1, 3, 5, 9, 10, 11), включая первый и «сохрани цель». Итог в ходе 12 отвечает на финальную цель: модель просит переход, решает единая таблица, правила не менялись. Он содержит узкую неточность «закрытие шага код не проверяет» (цитата: код проверяет границы плана). Тест на незаконный переход и видимость отказа из ходов 2 и 4 в итог не вошли.
