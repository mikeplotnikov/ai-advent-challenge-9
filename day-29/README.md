# День 29 — оптимизация локальной LLM под RAG

Go-приложение сравнивает исходный профиль дня28 с настройками температуры,
лимитов, короткого промпта и Q8 той же версии Qwen. Поиск, корпус, индекс,
контракт JSON и проверка дословных цитат сохранены. Ответы не переписываются.
Измерения и выбранный профиль — в [RESULTS.md](RESULTS.md).

## Живая витрина для записи

Из корня репозитория, до включения записи экрана:

```sh
brew services start ollama
ollama pull qwen3:4b-thinking-2507-q8_0
go run ./day-29
```

Откройте http://127.0.0.1:8029/?record=1. Дальше всё происходит в браузере:
выбор вопроса/профиля, произвольный ввод, парный запуск, источники, замеры,
отмена и сброс. Публичная страница https://challeng.mikeproject.dev/day-29/?record=1
показывает сохранённые реальные прогоны; она не подключена к Mac.
Видео и комментарий в таблице публикует владелец.

Нужен исходный индекс `day-21/index/structure.json` с SHA из capture; индекс
не хранится в Git по существующим правилам проекта. На машине владельца он
сохранён. Воспроизводимое восстановление исходного корпуса и индекса описано
в [дне21](../day-21/README.md); другой индекс не заменяет доказательства этого
эксперимента. На чистой копии verifier требует этот индекс и явно сообщает
об отсутствии. Установлены bge-m3 и Qwen с закреплёнными digest: смена версии
модели не является повтором измерения.

## Протокол сравнения

Сначала диагностические прогоны, затем замороженные профили и три повторения
исходного набора вопросов. Все кандидаты, включая ошибки, сохранены.
Один поиск на вопрос даёт одинаковый контекст всем профилям; генерации
последовательны. Порядок профилей меняется между повторами. Перед каждым
блоком генераторы выгружаются, выбранный профиль прогревается. Холодные
контроли измеряются отдельно и не входят в тёплую серию.

Полное время в таблице — сумма измеренного общего поиска и генерации профиля,
а не новый wall-clock вызов всего pipeline для каждой строки. Сохраняются
prompt/eval/load timings Ollama, исходные запросы/ответы и повторы формата.
Explicit `truncate:false` и `shift:false` запрещают скрытую потерю контекста;
это общая защита всех профилей, проверенная на установленной Ollama.

`size`/`size_vram` относятся к выбранному генератору из `/api/ps`. RSS — сумма
RSS процессов runner Ollama с выборками250мс; на этой версии это llama-server.
Эти показатели на Mac не складываются, RSS не является полным расходомMetal.
Краткие пики могут быть пропущены. Ошибки выборок сохранены; энергия не измерялась.
Размер весов на диске хранится отдельно в identities.size_bytes.

Факты сверяются с прежними эталонами. Смысловая поддержка ответов оценивается
независимо и привязана к SHA raw run. Совпадение дословной цитаты доказывает
её происхождение, но не истинность всего ответа. Отказы вне базы и пропуски
внутри базы различаются. Скорость сравнивается на одинаковых поддержанных
содержательных парах, чтобы нельзя было победить за счёт быстрых отказов.
Проверяется известный небольшой набор; обобщения и статистическое превосходство
не заявляются. Правило выбора и все исходные данные доступны в report.py/run.json.

## Проверка и воспроизведение

```sh
go test ./... -count=1
go vet ./...
go test -race ./day-29 -count=1
python3 day-29/report_test.py
python3 day-29/report.py --check
```

Новый самостоятельный прогон создаёт новый файл и не перезаписывает измерение:

```sh
go run ./day-29 -eval-out /tmp/day29-new-run.json
```

Для новых результатов потребуется новая независимая смысловая оценка по SHA.
Исходные diagnostics и холодные контроли остаются отдельными файлами; основной
run.json не смешивает их с итоговой серией. report.py формирует capture, сводку,
RESULTS и контрольную сумму автоматически; без измеренного улучшения проверка
готовности не проходит.

Сервер слушает loopback; Host/Origin/Fetch-Site, размер тела и входа, занятость,
таймауты, redirect/proxy/remote-model metadata проверяются. Во время генерации
сбои, незавершённый ответ и ошибки JSON/источника видны отдельно. Полная сетевая
изоляция daemon и физическое отключение интернета не проверялись.

Исправления после независимой проверки не меняли профили, вопросы, поиск или
исходные ответы. Первая смысловая оценка сохранена как
`semantic-review-first-invalid.json`: в ней смешивалась поддержка цитатой и
поддержка непроцитированным контекстом. Повторная независимая оценка применяет
единый критерий к всем группам ответов. Скорость сравнивается после отбраковки
недопустимых профилей; их ошибки больше не обнуляют сопоставимый набор.

В живом запросе переход между окнами одной модели сохраняется в observed_ps.
В size/memory_bytes входит только запись с запрошенным context_length. Сумма
RSS относится ко всему времени запроса и может включать предыдущий runner при
смене профиля. Исходная версия sampler итоговой тёплой серии сохранена в
resources-measured.go.txt; во всех её положительных выборках окно совпадает
с профилем, что дополнительно проверяет report.py.
