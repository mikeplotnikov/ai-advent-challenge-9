# День 14 — инварианты: то, что нарушать нельзя

Задание: «Добавьте в ассистента инварианты, которые он не имеет права нарушать. Сделайте
так, чтобы инварианты хранились отдельно от диалога, ассистент явно учитывал их в
рассуждениях и отказывался предлагать решения, которые их нарушают. Проверьте, что
происходит при конфликте запроса и инварианта и как ассистент объясняет отказ.»

Реализация — в том же агенте недели 3 (`internal/agent/invariants.go`,
`invariants_run.go`), интерфейс — тот же CLI `day-06` под флагами
`-layers -invariants`. Здесь, в `day-14/`, лежат набор правил `invariants.json`,
драйвер замера, сырые строки прогона `cells.jsonl` и отчёт `RESULTS.md`, собранный
из них.

## Чем инвариант отличается от ограничения профиля

День 12 уже дал профилю поле `constraints` — «чего роль не предлагает». Разница не в
формулировке, а в том, **чем правило держится**:

| | `constraints` (день 12) | инвариант (день 14) |
|---|---|---|
| откуда берётся | из выбранного профиля, меняется вместе с ним | из задачи или проекта, от профиля не зависит |
| чем держится | только промпт | промпт **плюс** проверка кодом после ответа |
| что при нарушении | плохой ответ, работа продолжается | повтор со списком нарушений, затем отказ |
| кто может править | команды профиля | отдельное хранилище, переживает сброс диалога |

Слайд 29, антипаттерн 03: «текстовые правила = просьба, LLM может нарушить, нет
гарантий» → «промпт + валидация после, двойная защита».

## Три области и два способа проверки

Области взяты из ответа ведущего в чате [#3152 → #3153, «Все так»]:

- `global` — для всех задач пользователя, свой файл;
- `task` — стек, архитектура, принятые решения, файл рядом с задачей;
- `transition` — запрет перехода в стейт-машине дня 13, включая «нельзя закрыть
  задачу без согласия пользователя».

Способы проверки — тоже его [#3155–3162]:

- `machine` — функция на Go по конечному словарю названий, ноль вызовов;
- `judge` — отдельный вызов модели-судьи для того, что линтером не проверишь.
  **Гарантии не даёт**, и агент это печатает: «внешняя ллм может помочь… но тоже
  не гарантия».

## Отказ объявляет модель, а не угадывает программа

Модель дописывает в конце строку `[[REFUSED: имя]]` — тот же механизм, которым день 13
читает `[[NEXT_STEP]]`. Первая версия угадывала речевой акт по списку подстрок и
пропускала обычную фразу «**вместо** долгих раздумий сразу возьмём Java и Spring Boot»:
«вместо» было в списке, всё предложение уходило из-под проверки. Отказ без маркера
считается обычным ответом — ошибка в эту сторону стоит лишнего отказа от программы, а
не пропущенного нарушения.

## Запустить

```bash
# диалог с инвариантами; -task обязателен: весь набор — области task/transition
go run ./day-06 -layers -task-state -invariants -task авторизация \
  -inv-load day-14/invariants.json

# замер: 6 рук × 5 сценариев × 20 повторов
go run ./day-14 -run -n 20

# отчёт из журнала; -rescore пересчитывает вердикты без новых вызовов
go run ./day-14 -report day-14/cells.jsonl
```

`RESULTS.md` строится **только** из `cells.jsonl`; правка руками ловится тестом
`TestTheCommittedReportIsWhatTheCommittedJournalBuilds`.
