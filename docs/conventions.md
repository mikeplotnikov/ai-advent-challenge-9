# Соглашения проекта

## Как устроен день

- Каждое задание — папка `day-NN/`. Если у дня есть программа, это пакет `main` в этой папке;
  запуск из корня репозитория: `go run ./day-NN …`.
- Исключения: в `day-07/`, `day-08/` и `day-09/` нет `main.go` — там данные и результаты замеров,
  а код этих дней живёт в `internal/agent` и запускается через `go run ./day-06`.
- `README.md` в папке дня есть начиная с `day-09/`; дни 1–8 описаны в корневом `README.md`.
  Если день что-то измеряет, рядом лежит `RESULTS.md` с цифрами прогона.
- Код, который нужен второму дню, переезжает в `internal/<пакет>`, а не копируется.
- Вспомогательные программы дня — в подпапках, например MCP-сервер `day-31/mcp-server/`.

## Как добавить новый день

1. Создать `day-NN/main.go` (`package main`) и `day-NN/README.md`.
2. Общее — брать из `internal/`: клиент модели `internal/llm`, MCP-клиент `internal/mcpclient`,
   цикл с инструментами `internal/toolagent`, RAG `internal/rag` / `internal/docrag`.
3. Если дню нужен свой ключ — читать `DEEPSEEK_API_KEY_DAYNN` через `llm.NewWithKeyEnv`;
   при пустой переменной клиент берёт общий `DEEPSEEK_API_KEY`. Добавить переменную в `.env.example`.
4. Сгенерированное локально (индексы, состояние, отчёты) — в `.gitignore`.
5. Добавить строку в таблицу `docs/architecture.md`.

## Ключи и окружение

- Ключи только в `.env` в корне (в `.gitignore`) или в переменных окружения;
  `llm.LoadDotEnv(".env")` подхватывает файл, не перекрывая окружение.
- Шаблон переменных — `.env.example`.

## Проверки

```bash
go build ./...
go vet ./...
go test ./...
```

Чтобы тест не платил за вызовы, модель подменяют интерфейсом (`toolagent.LLM`) или
переменной `DEEPSEEK_API_URL`, которая направляет клиент на локальный сервер.

## Что не коммитится

`.env` и `*.key`, сохранённые беседы `.sessions/`, бинарники `bin/`, локальные индексы
RAG (`day-21/index/`, `day-31/index/`), состояние и отчёты дней 18–20.
