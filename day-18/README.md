# День 18 — планировщик и фоновые задачи: агент, который работает 24/7

Задание дня 18 AI Advent Challenge #9: «Сделайте MCP-инструмент с отложенным или периодическим
выполнением … Инструмент должен: сохранять данные (JSON / SQLite), выполняться по расписанию,
возвращать агрегированный результат. Результат: Агент, который работает 24/7 и периодически
выдаёт сводку».

- **Сервер** `day-18/mcp-server` (официальный go-sdk v1.8.0, код в `internal/watchmcp` и
  `internal/watch`) — «наблюдения» за официальными курсами ЦБ РФ. Четыре инструмента:
  `create_watch` (коды валют и период опроса в минутах), `list_watches`, `stop_watch` и
  `get_watch_summary` (агрегат за окно). **Опрашивает ЦБ по расписанию сам**, без модели и без
  агента: в режиме MCP — горутиной планировщика, для cron — одним проходом `-once`. Всё хранится в
  одном JSON-файле: атомарная запись, `flock` на время чтения-изменения-записи, повреждённый файл
  не перезаписывается.
- **Агрегат** считает Go: опросы (всего, успешных, сбоев), публикации ЦБ (новые `rates_date`), по
  каждой валюте — первый и последний курс, минимум, максимум, среднее и изменение в рублях и
  процентах. ЦБ публикует курс раз в рабочий день, поэтому агрегат считается **по публикациям**,
  а не по опросам: частый опрос одного курса не перевешивает.
- **Агент** `day-18` — тот же цикл DeepSeek + MCP, что в дне 17 (`internal/toolagent`), без
  изменений. Разовый вопрос («следи за курсами доллара…») — модель сама вызывает `create_watch`.
  Сводка — модель вызывает `get_watch_summary` и пересказывает агрегат, запись уходит в
  `digests.json`.
- **24/7** — workflow `.github/workflows/day-18-agent.yml`: раз в час (минута 23) сервер опрашивает
  ЦБ (`-once`), агент выпускает сводку, если в её 3-часовом слоте сводки ещё нет (`-tick`), состояние
  коммитится в ветку [`day-18-state`](https://github.com/mikeplotnikov/ai-advent-challenge-9/tree/day-18-state/day-18).
  Живое состояние — на витрине `https://challeng.mikeproject.dev/day-18/`.

## Расписание — одно правило на всё

`slot(t, P) = floor(unix_seconds(t) / P)`. Наблюдение с периодом `M` минут опрашивается, если в
текущем слоте `M` опроса ещё не было. Сводка нужна, если в текущем слоте `-digest-every` её ещё
нет; неудачная сводка тоже занимает слот. Поэтому опоздание cron на несколько минут не сдвигает и
не пропускает опрос следующего часа, а два процесса на одном файле не опрашивают один слот дважды
(слот перепроверяется под блокировкой).

## Запуск

Из корня репозитория, ключ DeepSeek — в `.env` (`DEEPSEEK_API_KEY_DAY18` или `DEEPSEEK_API_KEY`).
Нужен доступ к `https://www.cbr.ru` (через некоторые VPN он не открывается).

```bash
go run ./day-18 "Следи за курсами доллара, евро и юаня — проверяй ЦБ каждую минуту"
go run ./day-18 -daemon -digest-every 2m -window 1h    # резидентный агент: опросы раз в минуту, сводка раз в 2 минуты
go run ./day-18 "Что с курсами за последний час?"
go run ./day-18 "Останови наблюдение"
go run ./day-18 -tick                                   # один проход для cron: сводка, если в слоте её нет
go run ./day-18/mcp-server -once                        # один проход опросов без MCP
go run ./day-18 -schema-cost                            # цена схем инструментов, 6 коротких обращений к модели
go run ./day-18 -report -until 2026-09-26T12:00:00Z -store state/day-18/store.json -digests state/day-18/digests.json
go run ./day-18 -sample /tmp/day18-sample               # детерминированный эталон для теста витрины
./day-18/demo.sh                                        # сцены скринкаста
```

Локальное состояние — `day-18/state/` (в `.gitignore`); чтобы начать с чистого листа, удалите
каталог. `-store` задаёт путь к хранилищу для команды сервера по умолчанию и для `-report`
(без пробелов: команда сервера делится по пробелам), `-command` заменяет команду сервера
целиком. Коды выхода: 0 — успех; 1 — ошибка MCP, DeepSeek, файлов или лимита шагов; 2 — ошибка
использования.

Остановить агента в GitHub: `gh workflow disable day-18-agent.yml`. После 20.10.2026 он
останавливается сам. Ключ в Actions — секрет репозитория `DEEPSEEK_API_KEY_DAY18`, другого workflow не
видит; серверу-подпроцессу ключи не передаются.

## Замер

`RESULTS.md` появится после суток работы в Actions: он генерируется `-report` из состояния ветки
`day-18-state` (ни одного числа руками) и отвечает на три вопроса — какую долю часов агент
действительно отработал, насколько надёжно модель вызывает инструмент агрегата и цитирует его
числа, сколько стоит сводка и отдельно схемы инструментов на каждом ходу (`-schema-cost`:
разность `prompt_tokens` одного и того же первого хода с `tools` и без).

## Как проверяется

```bash
go vet ./... && go test -count=1 ./...
```

Хранилище, слоты, агрегат, инструменты и их ошибки; три процесса на одном хранилище; планировщик
сервера по stdio на фейковом ЦБ; `-tick` и `-daemon` на фейковом DeepSeek, включая смерть
сервера-подпроцесса; отчёт с подменённой правой границей; детерминированность `-sample` и то,
что копия в витрине не устарела.

## Ограничения

- **24/7 — это cron GitHub Actions, а не постоянно запущенный процесс.** GitHub прямо допускает,
  что плановые запуски опаздывают, особенно в начале часа, и изредка пропадают. Поэтому доля
  отработанных часов меряется, а не заявляется. Резидентный режим `-daemon` — тот же агент для
  VPS.
- ЦБ отвечает 403 на User-Agent по умолчанию Go; клиент шлёт свой (`internal/cbr`).
- Опросы «последнего курса»: ЦБ устанавливает курс заранее, поэтому новая публикация обычно
  появляется днём накануне даты курса.
- Блокировка — `flock`: macOS и Linux, Windows вне объёма.
