# AI Advent Challenge #9 — задания

Репозиторий с решениями заданий челленджа AI Advent Challenge, 9 поток
(школа «Mobile Developer», 7 недель, старт 31.08.2026).

Язык — **Go**, взят намеренно вне зоны комфорта. Весь код пишет кодинг-ассистент
(Claude Code / Codex) — это правило челленджа, а не оговорка.

Модель — **DeepSeek** по REST напрямую у поставщика.

## Структура

| Папка | Что там |
|---|---|
| `internal/llm/` | клиент DeepSeek: одно место, которое умеет ходить в API |
| `day-01/` | неделя 1, день 1 — CLI: вопрос аргументом, ответ в консоль |
| `day-01-web/` | тот же вызов, но с чат-интерфейсом в браузере |
| `day-02/` | неделя 1, день 2 — один вопрос в четырёх режимах контроля ответа |

Дальше по одной папке на задание: `day-02/`, `day-03/`, …

## Запуск

```bash
cp .env.example .env   # и вписать свой ключ DeepSeek

# консольный вариант
go run ./day-01 "Привет! Расскажи о себе в двух предложениях."

# веб-вариант: открыть http://localhost:8080
go run ./day-01-web

# день 2: один и тот же вопрос под разным уровнем контроля
go run ./day-02 "Объясни, как работает HTTPS"
go run ./day-02 -json          # плюс тело каждого запроса целиком

# своя комбинация рычагов рядом с A: stop выключен — маркер останется в тексте
go run ./day-02 "Что такое рекурсия?" -custom format,marker,max=400

# детерминированность: один и тот же запрос 10 раз, схема ответа не должна поплыть
go run ./day-02 "Объясни, как работает HTTPS" -repeat 10
```

Браузер ключа не видит: страница обращается к своему серверу на Go (`POST /api/chat`),
а уже сервер идёт в DeepSeek. Порт меняется переменной `PORT`.

Ключ читается из `DEEPSEEK_API_KEY` — из переменной окружения или из файла `.env`
в корне репозитория. `.env` в `.gitignore` и в репозиторий не попадает. День 2 читает
`DEEPSEEK_API_KEY_DAY2`, а если его нет — тот же общий ключ.

## День 2 — уровни контроля ответа

Один вопрос уходит четырьмя запросами, и разница видна в цифрах, а не на слово:

| Прогон | Что задано | Чем |
|---|---|---|
| A | ничего | — |
| B | формат, длина, условие завершения | `system` + `max_tokens` + `stop` |
| C | жёсткий формат | `response_format: json_object` |
| D | только потолок длины | `max_tokens=60` |

Доказательства печатаются вместе с ответом: `finish_reason` (`stop` против `length`),
число токенов, срезан ли stop-маркер, разбирается ли ответ как JSON.

Пять рычагов, из которых собран каждый режим, — два в промпте и три в теле запроса:

| Рычаг | Где живёт |
|---|---|
| `format` — описание формата | `system` |
| `marker` — инструкция закончить `<<<END>>>` | `system` |
| `stop` — та же строка в поле `stop` | тело запроса |
| `json` — схема плюс `response_format: json_object` | и там, и там |
| `max=N` — потолок генерации | тело запроса |

Один ответ доказывает, что ограничение применилось. Что формат **детерминирован**,
доказывает только повтор: `-repeat N` шлёт один и тот же запрос N раз и проверяет каждый
ответ по объявленной схеме (`day-02/schema.go`) — совпали ключи, три шага, каждый строкой.
Отчёт разводит форму и содержание: сколько ответов легло в схему и сколько среди них
различалось. Вердикт не утверждает «данные разные», если данные совпали.

Флаг `-custom` собирает свою комбинацию и ставит её рядом с A. Он же закрывает
единственное место, где иначе пришлось бы верить на слово: если попросить маркер в
промпте, но **не** отправить поле `stop`, `<<<END>>>` остаётся в тексте ответа — значит
срезает его именно поле запроса, а не вежливость модели. То же самое живьём —
в песочнице на https://challeng.mikeproject.dev/day-02/ .

День 1 зафиксирован тегом `day-01-submitted` — состояние, которое смотрит куратор.
