# День 26 — запуск локальной LLM

Go runner выполняет три независимых запроса к локальной Qwen через Ollama HTTP API и сохраняет исходные запросы, ответы и метрики. Новое диалоговое приложение — отдельное задание 27.

## Запуск

Нужны Go из go.mod репозитория и Ollama. На машине, где выполнен прогон: Apple M1 Pro, 16 ГБ RAM, Ollama 0.33.2.

```sh
ollama pull qwen3:4b
# Если daemon не запущен, в отдельном терминале:
ollama serve
# Из корня репозитория:
go run ./day-26 -out /tmp/day26-repeat.json
```

При установке модели загружаются веса из каталога Ollama. Вызовы runner разрешены только по HTTP к literal loopback IP; localhost преобразуется в 127.0.0.1. HTTP proxy и redirects отключены. Перед генерацией /api/tags подтверждает установленную модель и digest, /api/show — completion capability и отсутствие remote_model/remote_host. Ключи облачных провайдеров не используются.

Это ограничение HTTP-клиента и проверка метаданных, а не packet capture или доказательство полной изоляции daemon от интернета. Внешние HTTP endpoints и облачные модели runner отклоняет.

## Что проверяем

1. Арифметика: 17 + 25, строгое соблюдение ответа одним числом.
2. Извлечение: город, дата и число участников из синтетического текста, правильные JSON-типы. Нормализованное имя города «Казань» уже задано в запросе; этот пример проверяет перенос заданного имени, извлечение даты и числа, а не самостоятельную нормализацию города.
3. Выбор занятий: соблюдение бюджета и времени, корректные суммы и максимальная полезность. Эталон вычисляется перебором всех наборов.

Градация сложности учебная. Проверка ответа отделена от успеха API: смысловая ошибка сохраняется с passed=false; HTTP-ошибка, некорректный JSON оболочки, пустой или незавершённый ответ прерывает запуск с exit 1. Новый файл создаётся только после трёх технически успешных ответов. Существующий файл не перезаписывается; выберите новый -out. Без -out используется уникальное имя в системной временной папке.

## Прогон и витрина

`showcase.json` — итоговый реальный прогон; `experiments/nonthinking.json` — первоначальный прогон с think=false. Итоговый capture — исходный полный прогон с think=false и num_predict=512; качество ответов не подгонялось. Дополнительная попытка think=true / num_predict=2048 сохранила корректные первые два ответа, но третий завершился reason=length и exit 1. Терминальный вывод сохранён в experiments/thinking-attempt.txt; сырой ответ незавершённого третьего запроса не сохранён, полноту этой трассы не заявляем.

См. `RESULTS.md`: таблица строится программно из capture. Витрина использует побайтовую копию JSON, показывает три ответа и трассы. HTTP-ответ хранится как разобранный JSON с сохранением значений, а не как побайтовая копия сетевого тела. Она не вызывает модель и не даёт браузеру доступ к Mac.

```sh
go vet ./...
go test ./... -count=1
python3 day-26/report.py --check
```
