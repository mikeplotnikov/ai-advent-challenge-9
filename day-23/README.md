# День 23 — реранкинг и фильтрация

Задание: добавить второй этап после поиска (фильтр релевантности или реранкер), настроить порог
отсечения и top-K до и после, добавить query rewrite и сравнить режимы.

## Конвейер

```
вопрос ─[rewrite?]→ bge-m3 → top-10 по косинусу → порог косинуса 0,45 → реранкер DeepSeek (0–3)
      → оценка ≥ 2 → top-3 → фрагменты + вопрос → DeepSeek → ответ
```

- **Порог косинуса 0,45** — дешёвый первый фильтр. Он ниже самого слабого эталона в top-10 дня 21
  (0,4596), поэтому не срезает ни одного известного эталона. Одного порога мало: у эталонов косинус
  0,46–0,68, у остальных чанков 0,41–0,65, распределения почти совпадают.
- **Реранкер** — отдельная модель, как кросс-энкодер из урока: `deepseek-flash` одним вызовом
  оценивает каждого выжившего кандидата (3 — содержит ответ, 2 — существенную часть, 1 — та же тема,
  0 — не о том), ответ в `json_object`, схема проверяется кодом. Остаются оценки ≥ 2, по убыванию
  оценки, не больше трёх.
- **Query rewrite** — `deepseek-flash` переписывает вопрос в поисковый запрос (термины + синонимы);
  эмбеддится переписанный запрос, а реранкер и ответ видят исходный вопрос.
- Если фильтр отсёк всё, модель не вызывается: ответ `[[НЕТ ДАННЫХ]]`.
- Промпты ответа — дословно из дня 22, индекс — `day-21/index/structure.json`.

Режимы: `plain` (день 22: top-5), `rewrite` (переписанный запрос, top-5), `filter` (фильтр и
реранкер), `rewrite_filter` (оба шага).

## Запуск

Нужны Ollama с `bge-m3` (`ollama serve`, `ollama pull bge-m3`), индекс дня 21 и ключ DeepSeek
(`DEEPSEEK_API_KEY_DAY23` или общий `DEEPSEEK_API_KEY` в `.env`).

```sh
go run ./day-23 -ask "Насколько блок состояния увеличил объём входа и цену запроса?"   # plain против rewrite_filter
go run ./day-23 -ask "…" -mode filter -cos 0.5 -min-score 3 -k-before 15 -k-after 2  # свои настройки
go run ./day-23 -eval     # замер (один раз; повтор — только после удаления run.json)
go run ./day-23 -report   # пересобрать RESULTS.md и showcase.json из run.json без вызовов
```

`-ask` печатает переписанный запрос, всех кандидатов с косинусом, оценкой реранкера и судьбой
(«в контексте», «ниже порога косинуса», «оценка ниже порога», «за пределами top-K»), затем ответ с
токенами и ценой.

## Как мерили

- **Поиск** — на 40 вопросах дня 21 с цитатой-эталоном: дошёл ли чанк с эталоном до модели и сколько
  чанков и токенов ушло в контекст; плюс два вопроса, ответа на которые в базе нет (x01, x02).
- **Ответы** — на 10 контрольных вопросах дня 22, оценка кодом дня 22 (факты шаблонами, маркер
  `[[НЕТ ДАННЫХ]]`), R = 1.
- Одна заранее заявленная проверка — точный тест Макнемара «эталон в контексте», `plain` против
  `rewrite_filter`.

Полный отчёт с таблицей по каждому вопросу — [`RESULTS.md`](RESULTS.md); сырьё — `run.json`.
