# День 19 — композиция MCP-инструментов

Один MCP-сервер `cbr-pipeline` предоставляет три шага: `fetch_rates` получает
официальные публикации ЦБ, `summarize_rates` считает сводку, `save_report`
сохраняет проверяемый Markdown-файл. Агент получает один вопрос и сам составляет
цепочку `fetch → summarize → save`.

Между шагами передаются не все строки, а `dataset_id` и `summary_id`. Каждый id
содержит первые 12 знаков sha256 соответствующего канонического JSON. Полный
датасет, сводка и оба хеша записаны в provenance-блок отчёта; проверка заново
считает сводку и хеши, рендерит весь файл и сравнивает его байт в байт.

## Запуск

```bash
# один вопрос → три вызова инструментов → файл в day-19/reports/
go run ./day-19 "Сводка по евро за сентябрь 2026, сохрани отчёт"

# та же цепочка через MCP без модели
go run ./day-19 -direct -currency EUR -from 2026-09-01 -to 2026-09-24

# независимая проверка сохранённого файла; код 1 при любой подмене
go run ./day-19 -verify day-19/reports/EUR_2026-09-01_2026-09-24_<hash>.md

# сохранить трассу модели и tools/call
go run ./day-19 -save trace.json "Сводка по доллару за последние две недели"

# определения и байтовые эталоны для JS-двойника
go run ./day-19 -dump

# 20 живых вопросов; тратит деньги и обращается к DeepSeek и ЦБ
go run ./day-19 -bench
```

Ключ берётся из `DEEPSEEK_API_KEY_DAY19`, затем из `DEEPSEEK_API_KEY`. Модель —
`deepseek-v4-flash`, temperature 0, лимит — 6 обращений. `-reports` меняет папку
отчётов; `-timeout` — общий таймаут.

## Что видно в трассе

Терминал печатает `tools/list`, каждый шаг модели, имя инструмента, точные
аргументы, короткий текст результата, токены и стоимость. После `save_report`
печатаются путь и `проверка: ok`. В текст `fetch_rates` попадают только id, хеш,
валюта, период, число строк, первая и последняя публикации; все строки остаются в
`StructuredContent`, поэтому контекст модели не раздувается.

## Канонический формат

- ключи объектов сортируются лексикографически на каждом уровне;
- пробелов нет, кодировка UTF-8, HTML-экранирование выключено;
- `nominal` и `count` — десятичные строки без дробной части;
- `value`, `unit_rate`, `mean`, `change_abs`, `change_pct` — строки ровно с шестью
  знаками после точки;
- числа разбираются и считаются в целых миллионных, деление округляется к
  ближайшему, ровно половина — от нуля.

## Замер

Вопросы и фиксированное для каждого вопроса «сегодня» лежат в
`bench-questions.json`; поэтому относительные периоды имеют проверяемые ожидаемые
даты. Последний вопрос охватывает только выходные без публикаций. Для него
«модель не выдумала курс» означает: `summarize_rates` и `save_report` не вызваны,
а после удаления дат в ответе нет числа с тремя и более знаками после запятой или
точки. `-bench` обновляет `bench.json` и `RESULTS.md`.

## Проверка кода

```bash
gofmt -l .
go vet ./...
go test ./... -count=1
go run ./day-19 -dump > /tmp/day19-dump.json
go run ./day-19 -dump | cmp - /tmp/day19-dump.json
```

Коды выхода CLI: `0` — успех, `1` — ошибка исполнения или непрошедшая проверка,
`2` — ошибка аргументов.
