# День 27 — локальная LLM в веб-приложении

Go-сервер раздаёт веб-чат и вызывает установленную Qwen через Ollama. Введите свой
вопрос, получите настоящий ответ, затем задайте уточнение: история передаётся модели.
«Новый чат» или перезагрузка очищает историю в памяти вкладки. Диск для диалога не используется.

## Запуск

Нужны Go из go.mod и Ollama с установленной qwen3:4b. Живой прогон сделан на Mac
с Ollama 0.33.2; новая загрузка весов при наличии модели не нужна.

```sh
ollama pull qwen3:4b
# Если daemon не запущен, в отдельном терминале:
ollama serve
# Из корня репозитория:
go run ./day-27
```

Откройте http://127.0.0.1:8027. Остановить сервер — Ctrl+C.
Можно выбрать другой loopback-порт: `go run ./day-27 -listen 127.0.0.1:8037`.
Используйте ровно адрес, напечатанный сервером; другие Host/Origin отвергаются.

## Как работает

Браузер отправляет историю на `/api/chat`. Go проверяет чередование user/assistant,
добавляет system-промпт и выполняет Ollama `/api/chat` с stream=false, think=false,
temperature=0, num_predict=2048, num_ctx=8192. Ответ отображается как текст, не HTML.
Кнопка «Новый чат» отменяет текущий HTTP-запрос и исключает запоздалый ответ из новой истории.
Ответы не обрезаются и не переписываются. Смотрите трассу последнего запроса.

Ограничения: до восьми ответов в диалоге, до 4000 символов в поле нового запроса;
серверный предел каждого сообщения 16000 байт и тела запроса 128 KiB. Выход, который
не завершился с done_reason=stop, показывается как ошибка, без добавления в историю.
Если ответ модели превышает предел сообщения, начните новый чат. Ошибка сохраняет
текст запроса для повторной отправки. Если Ollama недоступна при старте, сервер не запускается;
если она стала недоступна позже, ошибка отображается на странице.

Go слушает только loopback и разрешает только literal loopback Ollama URL. Прокси
и redirects отключены, установленность и remote_model/remote_host проверяются перед
каждым ответом. Облачные клиенты и ключи не используются. Все UI-ресурсы локальные.
Это ограничения приложения и проверка метаданных, а не packet capture daemon или
доказательство физического отключения интернета. Первичная загрузка весов требует сети.

## Проверка и витрина

```sh
go test ./day-27 -count=1
go vet ./day-27
python3 day-27/report.py --check
```

`showcase.json` — реальная двухходовая запись из браузера. `RESULTS.md` и SHA строятся
из неё через report.py. Вторая реплика содержит исходный ответ первой; см. трассу.
Qwen вернула лишние рассуждения даже с think=false: это ограничение модели показано честно.
Витрина воспроизводит запись; произвольные живые запросы выполняются в локальном приложении.
Инструкция скринкаста — в HQ `work/week-6/day-27-screencast.md`.

[чат] Задание: HQ `Чат/ChatExport_2026-10-07/result.json`, #4766, 06.10.2026.
Исходный текст: `Уроки/Урок 27 (06.10)/Урок 27 (06.10).txt`.
Официальный API: https://docs.ollama.com/api/chat.

При проверке варианта запроса без точки в конце модель исчерпала прежний лимит 768 токенов. Лимит увеличен до 2048: на этом варианте модель завершила ответ. Ошибки length по-прежнему не считаются успешным ответом; новый лимит не гарантирует завершения любого запроса.

Контекст модели ограничен num_ctx=8192. Лимит числа реплик сам по себе не гарантирует удержание длинного диалога в контекстном окне. Проверенный скринкаст содержит два хода.
