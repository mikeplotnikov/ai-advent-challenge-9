# День 20 — оркестрация нескольких MCP-серверов

Один агент читает ordered-реестр `servers.json`, запускает три независимых stdio-процесса и
показывает модели общий список из семи инструментов. Полное имя имеет вид
`<алиас>__<инструмент>`; маршрутизатор сохраняет сервер и исход каждого вызова в отдельном журнале.

## Запуск

```bash
# только реестр и объединённый tools/list, без модели
go run ./day-20 -list

# длинный поток через clock, rates и pipeline
go run ./day-20 "Сколько сегодня стоят 1000 долларов в евро по курсу ЦБ и как менялся евро за последние 14 дней? Сохрани отчёт."

# тот же демонстрационный поток кодом, без модели
go run ./day-20 -direct

# полная трасса без ключа в JSON
go run ./day-20 -save /tmp/day20-trace.json "Какой сегодня официальный курс евро?"

# другой ordered-реестр и общий таймаут
go run ./day-20 -servers ./my-servers.json -timeout 5m "вопрос"

# платные измерения — запускаются отдельно
go run ./day-20 -bench
go run ./day-20 -schema-cost

# детерминированный контракт для JS-двойника
go run ./day-20 -dump
```

Ключ: `DEEPSEEK_API_KEY_DAY20`, затем `DEEPSEEK_API_KEY`. Модель —
`deepseek-v4-flash`, temperature 0, не больше 10 обращений к модели. `-bench` и `-schema-cost`
тратят деньги и не запускаются обычной проверкой кода.

## Реестр

Корневой объект — `mcpServers`. Порядок записей сохраняется. Запись содержит обязательный
`command`, массив `args` и необязательный объект строк `env`. URL-серверы в этом дне запрещены.
Подпроцесс получает окружение агента без всех `DEEPSEEK_API_KEY*`, затем поверх него — `env` записи.
Реестр — доверенная исполняемая конфигурация: `command` запускается с правами текущего пользователя,
поэтому `-servers` нельзя указывать на полученный от постороннего файл без проверки.

Реестр по умолчанию запускает:

- `clock` → `day20-clock` (`current_date`, `shift_date`);
- `rates` → `cbr-rates` (`convert_currency`, `get_currency_rates`);
- `pipeline` → `cbr-pipeline` (`fetch_rates`, `save_report`, `summarize_rates`).

Каждый процесс живёт в своей process group. Закрытие, ошибка старта, timeout и потеря транспорта
завершают всю группу, включая бинарник, который породил `go run`.

## Трасса живого прогона

Живой засчитанный прогон L1 и его дословная трасса добавляются сюда оркестратором после отдельного
платного запуска. Реализация не подставляет демонстрационные числа вместо результата DeepSeek/ЦБ.

## Что видно в трассе

- ход модели (`step`), полное имя, аргументы и краткий результат инструмента;
- список серверов с `serverInfo`, протоколом, транспортом и объявленными именами;
- routing journal: `seq`, полное и исходное имя, алиас, `serverInfo`, транспорт, длительность и
  `ok | tool_error | rpc_error | timeout | unavailable | dead | limit`;
- итоговый ответ, токены, стоимость и длительность;
- `routedOK`, `orderOK`, `provenanceStrict`, число отклонённых вызовов.

Трасса не содержит API-ключ: ключ не передаётся MCP-процессам и не сериализуется.

## Правила проверки

`routedOK` требует, чтобы каждый ответивший вызов ушёл серверу, объявившему имя в `tools/list`.
`orderOK` проверяет по ходам модели, что каждый `*_id` появился в успешном результате более раннего
хода, дата не из вопроса используется только после более раннего `clock__current_date`, а инструмент,
чья схема объявляет свойство `date`, не вызывается без `date` в том же или более раннем ходе, чем
первый успешный `clock__current_date`. Нарушения печатаются с именем вызова.
`provenanceStrict` дополнительно требует найти каждую дату в вопросе или успешном результате более
раннего хода. Вызовы одного хода не считаются последовательными.

Маршрутизатор допускает 16 вызовов на прогон. 17-й возвращает модели:
`ОШИБКА ИНСТРУМЕНТА: лимит вызовов инструментов на запрос исчерпан (16)`.
Timeout даёт `ОШИБКА ИНСТРУМЕНТА: сервер <алиас> не ответил за 45 с`; потеря транспорта —
`ОШИБКА ИНСТРУМЕНТА: сервер <алиас> недоступен: <причина>`.

## Цена схем

`-schema-cost` трижды измеряет первый ход L1 без инструментов, только с `clock`, `rates`, `pipeline`
и со всеми тремя. В `RESULTS.md` попадают `prompt_tokens`, дельта к варианту без инструментов и
размер JSON схем. Первый ход не исполняет tool calls.

## Формат `-dump`

Детерминированный JSON содержит поля `registry`, `servers`, `tools`, `systemPrompt`, `limits`,
`model`, `temperature`, `pricing`, `clock`, `refusalTexts`, `sequences`, `traceGoldens`.
Clock и объединённый `tools/list` снимаются с fixture-backed in-memory серверов. В эталонах есть
ошибки clock, 17-й вызов, мёртвый сервер, неизвестное имя после лимита и same-step дата.
